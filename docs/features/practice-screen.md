# 연습 화면·실시간 피드백

## 1. 배경

배경은 [[design#1. 배경]]과 같다. 이 기능 고유의 요구는 연습 중 내가 탭한 것이 얼마나 틀렸는지를 탭하는 즉시 눈으로 보는 것이다. 연습이 끝난 뒤에만 보면 어느 순간에 어떻게 틀렸는지 연결이 안 된다.

## 2. 목표

- 사용자는 탭하는 순간 그 탭이 목표보다 빠른지 늦은지, 얼마나인지를 타이밍 트랙에서 본다.
- 사용자는 놓친 음표와 불필요한 탭을 시각적으로 구분해 본다.
- 사용자는 최근 탭 몇 개의 오차로 자기 경향(늘 늦음 등)을 본다.
- 연속으로 잘하면 템포가 올라가고, 연속으로 틀리면 내려간다. 원하면 끌 수 있다.
- 연습이 끝나면 결과 화면에서 지표와 틀린 구간을 본다.

## 3. 비목표

- 악보 위에 판정 마커를 겹쳐 그리기. 악보 읽기를 방해한다.
- 연주 도중 BPM·기준음 즉시 변경. 연습 화면에서 바꿀 수 있지만 지금 치는 단위(두 마디나 한 반복)가 끝난 다음부터 적용한다.
- 색만으로 판정 구분. 기호나 텍스트를 같이 쓴다.

### 실패로 볼 것

- 탭과 점 표시 사이에 눈에 띄는 지연이 있다.
- 판정이 확정될 때까지 점이 안 나타난다.
- 템포가 너무 자주 바뀌어 연습 흐름이 끊긴다.

## 4. 사용자 흐름

1. 연습 화면에 들어오면 위에서 아래로 악보, 타이밍 트랙, 탭 영역이 보인다.
2. 카운트인 후 악보 커서와 타이밍 트랙 커서가 같이 움직인다.
3. 탭하면 타이밍 트랙에 점이 바로 찍힌다.
4. 판정이 확정되면 점의 색·기호가 바뀐다. 놓친 음표는 지나간 뒤 Miss 표시가 뜬다.
5. 문제가 끝나면 결과 화면. 자동 템포가 켜져 있으면 다음 문제 BPM 이 바뀔 수 있다.

## 5. 기능 정의

### 화면 구성

| 순서 | 영역 | 내용 |
|---|---|---|
| ① | 악보 | 박자표, BPM, 음표, 현재 위치 커서. 판정 마커 없음 |
| ② | 타이밍 트랙 | 악보와 같은 시간축. 목표 시점 기준선, 탭 점, Miss, Extra |
| ③ | 탭 영역 | 화면 하단의 큰 영역. 양손 모드는 좌우 분리 |

- 모바일에서 스크롤 없이 탭 영역을 쓴다.
- 탭 영역은 스크롤·확대·더블탭 확대 같은 브라우저 제스처를 막는다.
- 타이밍 트랙은 기본으로 항상 보인다.
- 휴대폰 폭(600px 이하)에서 여러 마디 패턴은 한 줄에 한 마디씩 그리고, 줄마다 그 마디의 타이밍 트랙을 둔다. 커서는 지금 치는 줄에만 보인다. 연습 단위(두 마디)와 판정은 그대로다.
- 휴대폰 폭에서 다음 마디 미리 보기는 다음 단위의 첫 마디만 작게 보여 준다.
- 다음 마디 미리 보기는 타이밍 트랙 바로 아래, 오차 게이지보다 위에 둔다. 지금 마디 끝에서 다음 마디 첫 박으로 눈을 바로 옮길 수 있게 하기 위해서다.
- 위쪽 머리글은 버튼 글자를 줄바꿈하지 않고, 제목이 길면 버튼 아래 줄로 내린다.
- 휴대폰 폭에서 탭 영역은 항상 최소 120px 높이로 화면 안에 보인다. 악보 영역이 넘치면 악보 영역만 스크롤된다. 미리 보기는 전체 폭으로 그린 뒤 70% 로 줄여 음표 간격을 유지한다.

### 첫 화면 연습 탭

- 위에서 아래로 머리글(앱 이름, 연습·설정 탭), 빠른 연습 카드, 목록, 아래 고정 바 순서다. 목록이 남는 세로 공간을 모두 쓴다.
- 아래 고정 바에는 목록 종류(단계, 고정 패턴, 기타 스트로크, 양손, 폴리리듬), 옵션 요약 한 줄, 시작 버튼이 있다. 자주 누르는 조작을 엄지가 닿는 아래에 모으기 위해서다.
- 옵션 요약을 누르면 아래에서 시트가 올라와 방식, 문제 종류, 템포, 기준음, 목록별 옵션(스트로크 입력, 손, 폴리리듬 비율)을 고친다. 시트 바깥이나 닫기를 누르면 닫힌다.
- 빠른 연습 카드는 한 줄 높이로 줄인다.

### 뒤로가기

- 첫 화면 연습 탭이 아닌 곳(연습, 결과, 요약, 보정, 청음 화면, 설정 탭, 옵션 시트)에서 브라우저나 휴대폰의 뒤로가기를 누르면 첫 화면 연습 탭으로 돌아온다. 연습 중이면 "그만하기" 와 같이 중단한다.
- 첫 화면 연습 탭에서 뒤로가기는 브라우저 기본 동작(앱을 떠남)이다.
- 화면을 여러 번 옮겨도 브라우저 기록은 한 칸만 쌓는다. 그래서 뒤로가기 한 번이면 항상 첫 화면이다.

### 연습 중 설정 바꾸기

- 연습 화면에서 BPM(−5, +5)과 기준음(매 박, 첫 박만, 1마디씩 끄기, 끔)을 바꿀 수 있다.
- 바꾼 값은 지금 치는 단위가 끝난 다음부터 적용한다. 단계 흐름은 다음 칸, 패턴 반복은 다음 반복이다. 화면에는 "다음부터 85 BPM" 처럼 적용 예정 값을 보여 준다.
- 손으로 BPM 을 바꾸면 그 연습이 끝날 때 자동 템포를 적용하지 않는다.
- 조작부는 머리글 아래 "85 BPM · 매 박" 요약 버튼 하나로 접어 두고, 누르면 펼친다. 연습 화면 세로 공간을 아끼기 위해서다.
- 적용할 때는 지금 단위를 마저 친 뒤 새 BPM 으로 카운트인 1마디를 하고 같은 위치부터 이어서 친다. 진도, 시도 횟수, 통과 상태는 이어진다.

### 실시간 피드백

- 빠르면 기준선 왼쪽, 늦으면 오른쪽에 점을 찍는다.
- 점은 탭 즉시 미확정 상태로 그리고, 매칭이 확정되면 Perfect·Great·Good·Extra 로 갱신한다. 매칭이 나중에 바뀔 수 있어서 표시와 판정을 분리한다.
- Miss 는 목표 이벤트가 허용 범위를 지나도 매칭되지 않으면 표시한다.
- 최근 탭 오차 기록을 남긴다(개수는 미정).
- 양손 모드에서는 타이밍 트랙을 왼손·오른손 두 줄로 나눈다.
- 악보 커서와 타이밍 트랙 커서는 같은 재생 시각을 쓴다.
- 타이밍 트랙에는 박마다 옅은 점선과 박 번호(1 2 3 4)를 둔다. 당김음처럼 박 자리에 음표가 없을 때도 박 위치를 짚을 수 있게 하기 위해서다. 악보 위에는 그리지 않는다.

### 탭 소리

- 연습 화면에서 탭 영역을 누르거나 키를 누를 때마다 바로 짧은 탭 소리를 낸다. 판정과 무관하게 누른 모든 입력에 소리를 낸다.
- 소리는 입력 영역에 따라 다르다.

| 입력 영역 | 소리 |
|---|---|
| 한 영역 | 탭 소리(내 연주 다시 듣기와 같은 소리) |
| 기타 스트로크 다운·업 | 패턴의 다운·업 스트로크 소리 |
| 양손 왼손·오른손 | 탭 소리를 왼손은 낮게, 오른손은 높게 |

- 설정 탭에서 끌 수 있고 기본값은 켜짐이다. 출력 지연이 큰 기기에서는 소리가 늦게 들려 방해가 될 수 있기 때문이다.
- 지연 보정 화면에서는 탭 소리를 내지 않는다. 내 탭 소리가 들리면 틱 대신 그 소리에 맞추게 되어 보정값이 틀어진다.
- 탭 소리는 누른 순간 바로 재생하므로 기기 출력 지연만큼 늦게 들린다. 지연 보정값은 판정에만 쓰고 이 소리를 앞당기지 않는다.

### 자동 템포 (설정값, 초기 가설)

| 조건 | 동작 |
|---|---|
| 3회 연속 안정적 성공 | +5 BPM |
| 2회 연속 실패 | −5 BPM |
| 오차가 줄고 있지만 불안정 | 유지 |
| 매우 어려워하는 패턴 | 템포 감소 또는 패턴 단순화 |
| 새 리듬 유형 | 검증된 적정 BPM 에서 시작 |

- 성공·실패는 Hit Rate, MAE, Miss, Extra 를 종합해 판단한다.
- 변경은 문제 또는 반복 구간이 끝날 때만.
- 사용자가 끄고 BPM 을 고정할 수 있다. 자유 연습에서 특히.

### 결과 화면

- Hit Rate, MAE, 평균 부호 오차(빠른·늦은 경향), Miss, Extra
- 박자별 오차 시각화
- 틀린 구간, 재시도 버튼
- 모방 모드는 정답 악보와 내 입력 비교

### 탈락한 후보

| 후보 | 탈락 사유 |
|---|---|
| 연습 종료 후에만 피드백 (처음 기본값 안) | 사용자가 즉시 보기를 원함 |
| 실시간·마디 종료·연습 종료 중 선택 | 즉시 표시로 확정. 선택지는 필요해지면 추가 |
| 악보 위에 오차 점 표시 | 악보 읽기 방해 |
| Perfect·Good 텍스트만 표시 | 얼마나 빠르고 늦은지 위치로 안 보임 |
| 연주 중 BPM 즉시 변경 | 혼란 |

## 6. 설계

- 탭 → 화면 점 표시 경로는 판정 엔진을 거치지 않는다. 입력 계층이 타임스탬프를 화면 상태에 바로 넣고, 판정 결과는 별도로 갱신한다.
- 점은 다음 렌더링 프레임에 그려진다. 표시 지연은 주사율 영향을 받지만, 판정은 타임스탬프로 하므로 판정 결과는 바뀌지 않는다.
- 오디오 스케줄러는 UI 렌더링과 분리한다. 화면이 무거워도 재생 시각은 흔들리지 않아야 한다.
