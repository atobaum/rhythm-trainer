# 연습 화면·실시간 피드백

## 1. 배경

배경은 [[design#1. 배경]]과 같다. 이 기능 고유의 요구는 연습 중 내가 탭한 것이 얼마나 틀렸는지를 탭하는 즉시 눈으로 보는 것이다. 연습이 끝난 뒤에만 보면 어느 순간에 어떻게 틀렸는지 연결이 안 된다.

## 2. 목표

- 사용자는 탭하는 순간 그 탭이 목표보다 빠른지 늦은지, 얼마나인지를 타이밍 트랙에서 본다.
- 사용자는 놓친 음표와 불필요한 탭을 시각적으로 구분해 본다.
- 사용자는 최근 탭 몇 개의 오차로 자기 경향(늘 늦음 등)을 본다.
- 연속으로 잘하면 템포가 올라가고, 연속으로 틀리면 내려간다. 원하면 끌 수 있다.
- 연습이 끝나면 결과 화면에서 지표와 틀린 구간을 본다.

## 3. 비목표

- 악보 위에 판정 마커를 겹쳐 그리기. 악보 읽기를 방해한다.
- 연주 도중 BPM 변경. 문제나 반복 구간 경계에서만 바꾼다.
- 색만으로 판정 구분. 기호나 텍스트를 같이 쓴다.

### 실패로 볼 것

- 탭과 점 표시 사이에 눈에 띄는 지연이 있다.
- 판정이 확정될 때까지 점이 안 나타난다.
- 템포가 너무 자주 바뀌어 연습 흐름이 끊긴다.

## 4. 사용자 흐름

1. 연습 화면에 들어오면 위에서 아래로 악보, 타이밍 트랙, 탭 영역이 보인다.
2. 카운트인 후 악보 커서와 타이밍 트랙 커서가 같이 움직인다.
3. 탭하면 타이밍 트랙에 점이 바로 찍힌다.
4. 판정이 확정되면 점의 색·기호가 바뀐다. 놓친 음표는 지나간 뒤 Miss 표시가 뜬다.
5. 문제가 끝나면 결과 화면. 자동 템포가 켜져 있으면 다음 문제 BPM 이 바뀔 수 있다.

## 5. 기능 정의

### 화면 구성

| 순서 | 영역 | 내용 |
|---|---|---|
| ① | 악보 | 박자표, BPM, 음표, 현재 위치 커서. 판정 마커 없음 |
| ② | 타이밍 트랙 | 악보와 같은 시간축. 목표 시점 기준선, 탭 점, Miss, Extra |
| ③ | 탭 영역 | 화면 하단의 큰 영역. 양손 모드는 좌우 분리 |

- 모바일에서 스크롤 없이 탭 영역을 쓴다.
- 탭 영역은 스크롤·확대·더블탭 확대 같은 브라우저 제스처를 막는다.
- 타이밍 트랙은 기본으로 항상 보인다.

### 실시간 피드백

- 빠르면 기준선 왼쪽, 늦으면 오른쪽에 점을 찍는다.
- 점은 탭 즉시 미확정 상태로 그리고, 매칭이 확정되면 Perfect·Great·Good·Extra 로 갱신한다. 매칭이 나중에 바뀔 수 있어서 표시와 판정을 분리한다.
- Miss 는 목표 이벤트가 허용 범위를 지나도 매칭되지 않으면 표시한다.
- 최근 탭 오차 기록을 남긴다(개수는 미정).
- 양손 모드에서는 타이밍 트랙을 왼손·오른손 두 줄로 나눈다.
- 악보 커서와 타이밍 트랙 커서는 같은 재생 시각을 쓴다.

### 자동 템포 (설정값, 초기 가설)

| 조건 | 동작 |
|---|---|
| 3회 연속 안정적 성공 | +5 BPM |
| 2회 연속 실패 | −5 BPM |
| 오차가 줄고 있지만 불안정 | 유지 |
| 매우 어려워하는 패턴 | 템포 감소 또는 패턴 단순화 |
| 새 리듬 유형 | 검증된 적정 BPM 에서 시작 |

- 성공·실패는 Hit Rate, MAE, Miss, Extra 를 종합해 판단한다.
- 변경은 문제 또는 반복 구간이 끝날 때만.
- 사용자가 끄고 BPM 을 고정할 수 있다. 자유 연습에서 특히.

### 결과 화면

- Hit Rate, MAE, 평균 부호 오차(빠른·늦은 경향), Miss, Extra
- 박자별 오차 시각화
- 틀린 구간, 재시도 버튼
- 모방 모드는 정답 악보와 내 입력 비교

### 탈락한 후보

| 후보 | 탈락 사유 |
|---|---|
| 연습 종료 후에만 피드백 (처음 기본값 안) | 사용자가 즉시 보기를 원함 |
| 실시간·마디 종료·연습 종료 중 선택 | 즉시 표시로 확정. 선택지는 필요해지면 추가 |
| 악보 위에 오차 점 표시 | 악보 읽기 방해 |
| Perfect·Good 텍스트만 표시 | 얼마나 빠르고 늦은지 위치로 안 보임 |
| 연주 중 BPM 즉시 변경 | 혼란 |

## 6. 설계

- 탭 → 화면 점 표시 경로는 판정 엔진을 거치지 않는다. 입력 계층이 타임스탬프를 화면 상태에 바로 넣고, 판정 결과는 별도로 갱신한다.
- 점은 다음 렌더링 프레임에 그려진다. 표시 지연은 주사율 영향을 받지만, 판정은 타임스탬프로 하므로 판정 결과는 바뀌지 않는다.
- 오디오 스케줄러는 UI 렌더링과 분리한다. 화면이 무거워도 재생 시각은 흔들리지 않아야 한다.
