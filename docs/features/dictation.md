# 리듬 청음

## 1. 배경

배경은 [[design#1. 배경]]과 같다. 리듬을 듣고 어떤 음표와 쉼표로 이뤄졌는지 아는 능력은 탭으로 재현하는 능력과 다르다.

## 2. 목표

- 사용자는 리듬을 듣고 정식 악보 4개 중 정답을 고를 수 있다(선택형).
- 사용자는 리듬을 듣고 음표·쉼표·점음표를 골라 빈 악보를 완성할 수 있다(작성형).
- 제출하면 틀린 음표, 쉼표, 길이가 표시되고 정답 리듬을 다시 들으며 비교할 수 있다.

## 3. 비목표

- 음높이 청음
- 탭 타이밍 판정. 이 모드는 탭하지 않는다

### 실패로 볼 것

- 선택형 오답이 너무 쉽게 구별되거나 정답과 같은 리듬이다.

## 4. 사용자 흐름

1. 연습 탭 방식에서 "듣고 맞히기" 를 고르고 문제 종류(악보 고르기, 악보 완성하기)와 단계를 고른다.
2. 시작하면 한 단계에서 5문제를 낸다. "리듬 듣기" 는 한 마디 센 뒤 박 소리와 함께 리듬을 들려주고 몇 번이든 다시 들을 수 있다.
3. 고르거나 채워서 제출한다.
4. 맞힌 것과 틀린 곳을 보고, 정답과 내 답을 들어 비교한 뒤 다음 문제로 간다.
5. 5문제가 끝나면 맞힌 수를 보여주고 새 문제로 다시 하거나 목록으로 간다.

## 5. 기능 정의

### 악보 고르기

- 정답은 고른 단계의 생성 사양으로 새로 만든 패턴이다.
- 오답 3개는 같은 사양으로 만들고, 모자라면 앞 단계들의 사양으로 같은 박자·마디 수에 맞춰 만든다.
- 네 선택지는 들었을 때 서로 달라야 한다. 소리가 나는 시점의 목록이 모두 다르다.
- 제출 전에는 어느 것이 정답인지 표시하지 않는다. 제출하면 정답은 초록, 고른 오답은 빨강이다.

### 악보 완성하기

- 박 칸(박자 × 마디 수)을 팔레트의 음형으로 앞에서부터 채운다. 팔레트는 그 단계의 음형과 채우기 음형이다.
- 2박 음형은 마디를 넘어가는 자리에 넣을 수 없다. 칸이 다 차야 제출할 수 있다.
- 채점은 박마다 소리가 나는 시점이 같은지 본다. 틀린 박은 빨강으로 표시하고 "2마디 3박" 처럼 알려준다.

### 같은 리듬의 기준

- 소리가 나는 시점이 같으면 같은 리듬이다. 앱의 패턴 소리는 짧은 타악기 소리라서 4분음표와 "8분음표 + 8분쉼표", 붙임줄 표기와 긴 음표는 들어서 구별되지 않기 때문이다.
- 그래서 선택지끼리는 소리 나는 시점이 반드시 다르고, 작성형은 표기가 달라도 소리가 같으면 정답이다.

### 탈락한 후보

| 후보 | 탈락 사유 |
|---|---|
| 악보 구조가 같아야 정답 | 들어서 구별할 수 없는 차이로 틀리게 됨 |
| 음표 하나씩 넣는 팔레트 | 마디 길이 맞추기가 번거로움. 박 단위 음형이면 유효성이 저절로 맞음 |
| 오답을 정답의 음표 하나만 바꿔 만들기 | 단계 사양으로 만든 다른 패턴이면 충분히 헷갈리고 유효성 검사가 필요 없음 |

## 6. 설계

| 개념 | 담는 것 |
|---|---|
| 고르기 문제 | 선택지 4개, 정답 위치 |
| 완성하기 문제 | 정답 패턴과 그 박 단위 음형 목록, 팔레트, 전체 박 수 |
| 청음 결과 | 5문제 중 맞힌 비율을 실력 기록의 `dictation:음형` 항목에 남김 |
