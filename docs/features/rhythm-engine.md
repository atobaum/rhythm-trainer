# 리듬 엔진

## 1. 배경

배경은 [[design#1. 배경]]과 같다. 이 기능 고유의 맥락은 악보 기호와 실제 타격이 일대일로 대응하지 않는다는 점이다. 붙임줄로 이은 두 음표는 한 번만 치고, 쉼표는 치지 않으며, 헛스트로크는 소리 없는 손동작이다. 폴리리듬은 같은 시간을 3등분과 4등분처럼 서로 다르게 나눠서 부동소수점으로 누적하면 오차가 쌓인다.

## 2. 목표

- 리듬 패턴 하나를 하나의 데이터로 정의하면 악보 표시, 오디오 재생, 정답 타격 시각이 모두 거기서 만들어진다.
- 80 BPM 에서 8분음표 간격이 정확히 375ms 로 계산되고, 수백 번 반복해도 시각 오차가 쌓이지 않는다.
- 단일 리듬, 양손 두 트랙, 2:3·3:4 폴리리듬을 같은 모델로 표현한다.

## 3. 비목표

- 음높이 표현. 리듬만 다룬다.
- 악보 편집기 UI. 패턴은 JSON 과 생성기로 만든다.
- 4/4 이외 박자표의 MVP 지원. 모델은 지원하되 콘텐츠는 4/4 만 만든다.

### 실패로 볼 것

- 악보에 그려진 것과 판정 기준 시각이 서로 다르다.
- 양손이나 폴리리듬을 넣을 때 모델을 다시 설계해야 한다.

## 4. 사용자 흐름

사용자가 직접 보는 화면은 없다. 다른 기능이 이 엔진을 쓴다.

1. 콘텐츠(정적 JSON 또는 생성기)가 `RhythmPattern` 을 만든다.
2. 악보 렌더러가 Notation 정보로 악보를 그린다.
3. 오디오 스케줄러와 판정 엔진이 목표 이벤트(시각 목록)를 받는다.

## 5. 기능 정의

### 세 개념 분리

| 개념 | 질문 | 예 |
|---|---|---|
| Notation | 악보에 무엇을 표시하나 | 붙임줄로 이은 두 음표 |
| Performance | 언제 어떤 소리가 나야 하나 | 붙임줄 첫 음표의 onset 한 번 |
| Input | 사용자가 언제 무엇을 입력했나 | 탭 타임스탬프, 트랙, 방향 |

### 시간 표현

- 위치(onset)와 길이(duration)는 온음표 = 1 기준 기약분수다. 3:4 폴리리듬에서 왼손은 0, 1/3, 2/3, 오른손은 0, 1/4, 2/4, 3/4 에 놓인다.
- 목표 시각은 `t_i = t0 + (240000 / BPM) × onset_i` [ms]. ms 변환은 마지막에 한 번만 한다.
- 반복 회차 k 의 시각은 `t0 + (k × 패턴 길이 + onset)` 을 유리수로 계산한 뒤 ms 로 바꾼다.

| 이벤트 | onset | 80 BPM 목표 시각 |
|---|---|---|
| 1 | 0 | 0ms |
| 2 | 1/8 | 375ms |
| 3 | 1/4 | 750ms |
| 4 | 3/8 | 1,125ms |

### 이벤트 생성 규칙

- 쉼표는 목표 이벤트를 만들지 않는다.
- 붙임줄로 이은 음표는 첫 음표만 이벤트를 만든다.
- 헛스트로크(`motion: 'ghost'`)는 소리 이벤트를 만들지 않는다. 손동작 이벤트로 따로 둔다.

### 불변 조건

- Fraction 은 기약분수로 정규화하고 분모는 0 이 아니다.
- onset ≥ 0, duration > 0, 이벤트는 패턴 길이를 넘지 않는다.
- 단성 트랙의 음표·쉼표는 겹치지 않고 패턴 전체를 빈틈없이 채운다.
- 앱 콘텐츠는 빌드할 때 검사해서 위반하면 빌드를 실패시킨다. 런타임에서도 위반한 패턴은 거부한다.

### 패턴 생성

박자표, 사용 음표, 난이도 제약으로 패턴을 생성하고, 품질을 확인한 패턴만 고정 콘텐츠로 쓴다. 같은 시드면 같은 패턴이 나온다.

### 탈락한 후보

| 후보 | 탈락 사유 |
|---|---|
| 박자 위치를 ms 나 부동소수점 박 단위로 저장 | 폴리리듬·셋잇단음표에서 누적 오차, BPM 변경 시 재계산 필요 |
| 16분음표 그리드 인덱스로 저장 | 셋잇단음표와 폴리리듬을 표현할 수 없음 |
| 화면에 그린 악보 구조를 그대로 저장 | 오디오·판정이 기호 해석을 다시 해야 함 |
| 단일 리듬 전용 모델 후 양손 확장 | 확장 시 엔진 재작성 |

## 6. 설계

### 데이터

| 개념 | 담는 것 |
|---|---|
| 패턴 | 제목, 박자표, 마디 수, 트랙 목록, 리듬 요소 태그, 난이도 |
| 트랙 | 역할(단일, 왼손, 오른손), 악기(탭, 타악기, 기타), 이벤트 목록 |
| 이벤트 | onset·길이(유리수), 음표인지 쉼표인지, 기보 정보(점, 튜플릿, 붙임줄 묶음), 강세, 스트로크(방향, 소리·헛스트로크) |
| 문제 | 모드(읽기, 모방, 청음 선택·작성, 양손, 폴리리듬, 스트로크), 패턴, BPM, 카운트인 마디 수, 미리 듣기 횟수, 연습 중 악보 표시 여부, 박자 가이드, 반복 횟수, 청음 선택지 |

### 소유와 검증

- 패턴과 문제는 `src/content/` 정적 JSON 이다. 앱 배포가 source of truth 이고 사용자는 수정하지 않는다.
- 콘텐츠는 빌드할 때 불변 조건을 검사하고, 위반하면 빌드가 실패한다. 런타임에서도 같은 검사를 하고 위반한 패턴은 거부한다(생성기가 만든 패턴, 저장 데이터 대비).
- 엔진은 순수 함수만 제공하고 상태를 갖지 않는다.
